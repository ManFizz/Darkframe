# Darkframe

Десктопный медиа-менеджер на Electron + React: локальная библиотека (коллекции, теги,
рейтинги, умные коллекции, редактор, видео-инструменты) и просмотр удалённых источников.

## Требования

- Windows 10/11 (основная платформа)
- Node.js **22.18+** (рекомендуется 24 LTS — тот же Node, что внутри Electron 44) и npm 10+
- Git

Скрипты установки разрешены явно (`allowScripts` в `package.json`) только тем пакетам,
которым нужно скачать или собрать бинарники: ffmpeg-static, sharp, sqlite3. При обновлении
их версий — `npm approve-scripts <пакет>`.

## Установка с нуля

```bash
git clone https://github.com/ManFizz/Gallery.git
cd Gallery
npm ci
npm run build
```

`npm ci` ставит зависимости строго по `package-lock.json`, а затем (`postinstall`)
выполняет `tools/prepare.js`:

- создаёт `data/settings.js` и `data/private.js` из шаблонов `*.template`, если их нет
  (существующие файлы не трогаются);
- компилирует SCSS из `src/css/*.scss` в `src/css/*.css`.

После первого запуска проверь `data/private.js` (ключи API r34 и т. п.) и
`data/settings.js`. Пустой `LibraryPath` = библиотека в `%APPDATA%/js-gallery/library`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run build` | подготовка + сборка webpack + запуск приложения |
| `npm run bundle` | подготовка + сборка webpack, без запуска |
| `npm run bundle:dev` | то же, но без минификации и с картами исходников — для отладки |
| `npm run view` | запуск уже собранного приложения |
| `npm run prepare:env` | только настройки из шаблонов + SCSS |
| `npm test` | тесты |
| `npm run smoke` | запуск собранного приложения на временной пустой библиотеке и проверка, что UI отрисовался без ошибок |
| `npm run check:fresh` | полная проверка «как на новой машине»: клон → `npm ci` → сборка → тесты → smoke |

`check:fresh` клонирует **закоммиченный** HEAD (незакоммиченные правки в проверку не
попадают); `node tools/fresh-check.js --remote` клонирует origin, `--keep` оставляет папку.

## Тесты

`test/*.test.js`, встроенный `node:test`, без дополнительных зависимостей. Запускаются на
Node внутри Electron (`ELECTRON_RUN_AS_NODE`), то есть в той же среде, что и main-процесс.

Тесты main-процесса работают через `test/helpers/sandbox.js`: подменяет модуль `electron`
и создаёт реестр библиотек с временной базой. Реальная `data/data.db` тестами не
открывается никогда.

Что покрыто:

- `filterPredicate` и `imageAdjust` — фильтры / умные коллекции и цветокоррекция редактора;
- `phash` — поиск похожих изображений;
- `ffmpegOps` — обрезка видео, кадры, превью;
- `database` — схема и миграции на пустой базе, индексы, сохранение тегов r34,
  список тегов библиотеки, теги у элементов;
- `import` — порядок импорта по дате файла, дубликаты, файлы в корзине, события для UI;
- `requires` — регистр имён в `require`/`import` совпадает с файлами на диске
  (на Windows несовпадение грузит модуль дважды), все модули `server/` загружаются.

## Данные

- Реестр библиотек: `%APPDATA%/js-gallery/libraries.json`. Он общий для всех копий
  проекта на машине. Чтобы запустить вторую копию изолированно, передай
  `--user-data-dir=<папка>` и положи туда свой `libraries.json`, как это делает
  `tools/smoke.js`.
- Библиотека по умолчанию (legacy): `data/data.db` + `LibraryPath/items`.
- `data/*.js`, `data/*.override.json`, `*.db`, `dist/`, скомпилированный CSS — не в git.
